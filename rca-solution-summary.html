03模块A · 代码中文描述（对比方案）

目标：将代码转为中文功能描述（保留类名、函数名，具体实现用中文描述），作为 CodeGraph 节点的语义摘要，喂给 LightRAG 做语义检索与根因推理。

业界范式参考：Google 的 Natural Language Outlines（FSE'25 会议论文）——用简洁散文分步概括函数主逻辑，LLM 可高质量生成；IBM Granite 的 code summarization 实践；以及 Agent4cs 多智能体分层摘要。本项目不造轮子，复用 opencode 订阅大模型实现。

四种实现方案对比

方案做法粒度token成本语义质量Win可用复用订阅LLM推荐
甲·函数级NL大纲AST切分到函数→逐函数LLM生成中文大纲(保留函数名,实现用中文分步描述)函数中高✓✓推荐
乙·文件级摘要整文件喂LLM→生成中文功能概述文件低中✓✓—
丙·分层摘要(类→方法)多Agent自底向上:方法摘要→类摘要→模块摘要(Agent4cs范式)分层高高✓✓大规模时
丁·现成代码注释工具基于AST的自动docstring生成(非LLM)函数极低低✓—不推荐
决策：方案甲（函数级 NL 大纲）为主，丙（分层）为大规模仓库的升级 函数级中文大纲与 CodeGraph 的函数节点天然对齐：每个函数节点附带一段"函数名 + 中文实现描述"，既保留可追溯的符号名，又有可检索的中文语义，直接作为 LightRAG 实体描述注入。

函数级中文大纲 Prompt 要点

函数级中文大纲 · 生成PromptPROMPT
# 角色：代码语义化专家。复用 opencode 订阅大模型。
# 输入：函数签名 + 函数源码（由 CodeGraph/codegraph 符号提取获得）
你是代码语义化专家。给定函数，输出中文功能大纲。
要求：
1. 保留类名与函数名（原文符号，便于回溯定位）
2. 实现逻辑用中文分步描述（每步一句，简洁）
3. 标注输入参数、返回值、副作用、异常路径
4. 若涉及外部调用（DB/RPC/缓存），显式标出
输出JSON：
{
  "symbol": "OrderService.create",
  "file": "OrderService.java:42",
  "cn_summary": "创建订单：1.校验参数 2.查库存 3.写入订单表 4.发MQ 5.返回订单号",
  "external_calls": ["库存RPC", "订单表DB", "MQ发送"],
  "failure_paths": ["库存不足抛InsufficientException"]
}

中文化与 CodeGraph / LightRAG 的衔接

  • CodeGraph 节点增强：CodeGraph 提取的每个函数符号节点，附加 cn_summary 字段，作为节点描述属性。
  • 注入 LightRAG：把"函数符号 + 中文描述"作为实体描述，经 insert_custom_kg 注入 LightRAG 图谱，使其可被中文语义检索命中。
  • 增量中文化：仅对根因分析涉及的嫌疑子图函数做中文化（按需），而非全仓，控制 token 成本。

04模块B · CodeGraph 代码图谱（克隆后自动构建）

CodeGraph 四层架构

源码文件 │ ▼ ┌──────────────────┐ │ tree-sitter 解析 │ ← 生成AST(增量,容错,纯C,快) └────────┬─────────┘ │ ▼ ┌──────────────────┐ │ 符号·边提取 │ ← 函数/类/方法 + 调用/继承/引用 └────────┬─────────┘ │ ▼ ┌──────────────────┐ │ SQLite 图谱存储 │ ← FTS5全文搜索 + 关系图 └────────┬─────────┘ │ ▼ ┌──────────────────┐ │ MCP Server │ ← 暴露给opencode/AI工具查询 └──────────────────┘

CodeGraph 基准实测（7 个真实开源仓库中位数）：平均省 35% 成本 / 59% token / 49% 耗时 / 70% 工具调用。大型仓库（如 VS Code ~10k 文件）收益最大，agent 几乎零文件读取即可回答架构问题。

opencode-codegraph 插件能力

npm 包 opencode-codegraph@0.1.38 是 opencode 官方支持的插件，对接 CodeGraph 的 CPG（Code Property Graph）。在 opencode.json 注册后，对话中提及文件即自动注入 CPG 上下文（方法数、圈复杂度、fan_in/fan_out、安全发现、调用关系），并支持污点分析。

opencode.json · 插件注册JSON
{
  "plugin": ["opencode-codegraph"],
  "mcp": {
    "codegraph": {
      "command": "codegraph",
      "args": ["mcp"],
      "env": { "CODEGRAPH_DB": "./.codegraph/graph.db" }
    }
  }
}

065-Agent 智能引擎

LangGraph 状态机编排，A2/A3 并行 fan-out，A4 fan-in 聚合做四维关联。

┌──────────┐ START ──► A1 问题理解 ──┬─► A2 代码分析 ──┐ │ ├─(fan-in)─► A4 根因分析 ──► CRAG门 ──► HIL门 ──► A5 方案 ──► END └─► A3 链路分析 ──┘ (Top3) (并行fan-out) (四维关联)
Agent职责核心能力
A1 问题理解拉云捷Bug单→抽取症状/报错→生成检索Query→定位嫌疑服务云捷Adapter + LLM抽取
A2 代码分析opencode拉码→CodeGraph构建图谱→沿报错栈静态污点追踪opencode-codegraph + 中文大纲
A3 链路分析按时间窗拉Trace→重建span树→识别异常传播路径TraceAdapter + 异常检测
A4 根因分析四维关联交叉验证→剪枝排序→输出Top-3根因静态∩运行时交集
A5 方案生成检索历史修复+最佳实践→生成补丁建议+验证用例LightRAG high-level

根因 5 步算法

  1. 定位范围：嫌疑服务 + CodeGraph 调用子图
  2. 断言异常：Trace 异常 span + Metric 异常点
  3. 挖掘关联：四维交集 + LightRAG 相似案例
  4. 剪枝排序：置信度 score 排序，保留 Top-3
  5. 输出 Top-3：每条含根因描述/置信度/证据链/定位函数

07双图谱与交叉验证（核心创新）

双图谱 = 服务级拓扑图（Trace+CMDB 聚合）+ 函数级调用图（CodeGraph 自动构建）。跨层 CONTAINS 关系实现服务→函数下钻。

图谱粒度构建用途
服务级拓扑图微服务/接口Trace + CMDB 聚合跨服务根因传播
函数级调用图函数/方法CodeGraph(opencode插件,自动)精确到函数定位

静态 × 运行时交叉验证

核心洞察：CodeGraph 静态调用图 ∩ Trace 异常传播路径 的交集函数置信度最高——既静态可达又运行时确实异常，大幅压低误报。

交叉验证 · 伪逻辑PSEUDO
# A2输出静态嫌疑函数集 S_static (CodeGraph调用图上反向BFS)
# A3输出运行时异常路径 P_runtime (Trace span映射到函数)
candidates = []
for f in S_static:
    if f in functions_of(P_runtime):       # 静态嫌疑 且 运行时异常路径命中
        score = w1*static_depth + w2*runtime_anomaly + w3*metric_corr + w4*change_recency
        candidates.append((f, score))
top3 = sorted(candidates, desc)[:3]   # Top-3根因

08双闸门与知识飞轮

双闸门机制

检索证据 ─► CRAG自动纠偏门(机器) ─► A4根因 ─► HIL人工确认门(人) ─► A5方案 │ 评估 │ 置信度<τ │ 人工Review ▼ ▼ ▼ [相关/模糊/不相关] 触发HIL [确认/修正/驳回] 相关:精炼 模糊:补检 不相关:改写Query重检索
  • CRAG 门（机器层）：LightRAG 重排器评估证据相关性，三档处理——相关精炼、模糊补检、不相关改写 Query 重检索。
  • HIL 门（人）：Top-3 置信度低于阈值 τ 时挂起任务，前端推送确认面板，人工确认/修正/驳回后回灌 A4。

知识飞轮回写

工单解决后结构化回写知识库：抽取根因/根因函数/调用路径/修复补丁/验证用例 → BGE-M3 向量化 → LightRAG ainsert → 图谱 SIMILAR_TO 边 → 增量更新社区摘要。平台随工单积累自学习，越用越准。

V3.0 全部组件 Win 原生可用，无需 Docker（LightRAG pip 直装、CodeGraph 有 install.ps1、opencode 跨平台）。满足"本地可调试"硬约束。

irm https://raw.githubusercontent.com/.../install.ps1 | iex
# 2. 装 LightRAG
pip install "lightrag-hku[api]"
# 3. 配 opencode.json 注册 codegraph 插件 + MCP
# 4. 配 LightRAG .env 指向 opencode 订阅LLM端点

12关键创新与方案对比

🧩

① opencode原生代码图谱

用 opencode-codegraph 插件 + CodeGraph 自动构建函数级调用图，替代手写 tree-sitter，不造轮子，多语言+增量+MCP原生。

🀄

② 代码中文语义化

opencode 订阅 LLM 按函数级 NL Outline 范式生成中文大纲，保留符号名+中文实现描述，提升检索可读性与命中率。

🔗

③ 静态×运行时交叉验证

CodeGraph 调用图 ∩ Trace 异常传播路径 = 高置信罪魁，压低静态/单维分析误报。

🎯

④ LightRAG双层级检索

low-level实体检索(历史经验)+high-level主题摘要(全局)，Win原生pip，弃用重部署的RAGFlow。

🛡️

⑤ 双闸门控幻觉

CRAG机器自动纠偏 + HIL人工兜底，分级管控LLM幻觉风险。

🔄

⑥ 知识飞轮自学习

工单解决即回写LightRAG+图谱，平台越用越准，随历史积累增益。
